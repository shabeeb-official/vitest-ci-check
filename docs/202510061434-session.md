# 202510061434: How

Currently every reload creates a new session and there is no way to persist data
across page reloads or navigation between the host site and our app. This
provides a unique situation where if the user goes to any page that is outside
of our app it causes the page to reload and our session is reset along with
products and chat history, this needs to be changed an this is causing a UX
issues for the customer. 

To overcome this issue we have to think about how session is recreated, if it is
created in each reload there is no point in saving the chat or products as
stated above. So if session is to be reused, which is the only way, we need to
find a way to identify when the session should be recreated, this needs to be
thought about in detail as this can cause issues to the AI like **Hallusinations** and similar

#### Proposed Solution

- Store session_id in sessionStorage
- Save products and chat history in sessionStorage as well
- The saved products and chat history will be under the name chat-<session_id>
  this will help to pick the correct products and chat history if in any case
  more than one products or chat histories is present in sessionStorage.

Why the sessionStorage is chosen is because sessionStorage will be cleared
automatically when the tab is closed, so every tab will have a separate
sessionStorage and will not collide with each other. If we end up using other
storage solutions like `localStorage` or `IndexedDB` it will be a lot of
overhead to keep the data in sync with the website as there can be overlap
between the previous sessions and current session.

But there are a questions that needs to be answered:
- How is session recreated
- How to clear old products and chat histories
- Is there any way to know if a browser page is reloaded or navigated

The above concern can be address by using the
`performance.getEntriesByType("navigation")`. The native JavaScript function
gives a way to know if the navigation type is a reload, navigation or some other
type of navigation, so using this function we can check if the page is reloaded
or just navigated.

If the page is navigated like going to favorites and coming back we can reuse
the session we have, which will resolve the issue of data not persisting, and
when the page is reloaded we can create a new session and clear the products and
chat history. I believe this will be the most optimal solution as these events
are triggered by the browser and we are listening to it and based on the
condition we are either reusing the existing session or creating a new one.

We can have a expiry time for each session, after which a new session will be
created. The will also clear all the products and chat histories related to the
`session_id`. The expiration of the session can be handled by adding a expiry
timestamp to the session and every time the session_id is read we can check if
the time is expired and if it expired create a new session and use it, this will
cause all the products and chat histories to be cleared as well.
